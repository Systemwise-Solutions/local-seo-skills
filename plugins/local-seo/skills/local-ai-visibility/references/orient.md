# Orient: what AI visibility needs, and where to find it

Find each piece yourself first. Ask the user only for what you can't find, in one message, and say why you need it.

| The check needs | Look here first | Why it matters |
|---|---|---|
| Every name the business goes by, and its domain | The site (header, footer, about page, legal name), the Maps listing, the brief | The runs file counts a mention only if it matches a name or alias. A previous name, or a short form customers use, missed here means undercounting. |
| What it offers, in customers' words | Site navigation and service or product pages, the profile's services, Search Console queries, the brief | Becomes the prompts. Assistants are asked in plain language, not keywords. |
| The reason people choose it | Reviews (what customers praise), site copy, the user | Gives the "for whom" prompts where specialists win or lose. |
| The area, in the ways people say it | The profile, location pages, the brief | Town, neighbourhood, and a landmark or "near me". For a business that travels to customers, the towns it covers. |
| Who it loses to | The brief, the user, the audit's grid results if the log has them | The comparison prompt and the "who is named instead" benchmark. The runs will show others; add them as they appear. |
| Which assistants its customers use | The user; GA4 referral sources if connected | Measure the ones they'll keep measuring. Default when unknown: ChatGPT, Gemini, and Google's AI Overviews and AI Mode. |
| Whether the lower rungs are sound | `local-seo-brief.md`, `local-seo-log.md`, a recent audit, the profile, a `site:` search | A suspended profile or an unindexed site comes first; work here is wasted until they're fixed. |
| Rules on what it can say | The lens in loop.md, any regulator or professional body named on the site | Limits the copy you write. Find the rule before writing. |
| One location or many | Location pages, store finder, the brief | Many: same prompt set per location with the area swapped, starting with a sample of three. |
| What prompted this | The conversation | A customer's report, one screenshot, a drop in AI visits, or curiosity. A single screenshot is a reason to measure, not a finding. |
| Data already collected | Connected tools (SearchOps may already track prompts for the location), earlier runs files, the log | Reuse the same prompts so months compare. Don't rebuild a set that's already being tracked. |
| Who it's for | The conversation, the brief | Owner, in-house team or agency client changes the wording and white-labelling, not the method. |

## Writing the brief

If a brief exists, confirm it in one line and update only what changed. If not, write `local-seo-brief.md` with plain labels (other skills read it): the business and every name it uses, website, profile, the shape from the lens, money searches, area, competitors, audience, data available, constraints. Add the assistants checked and the prompt set (or the file it's in), so the next run reuses them exactly. Keep it short and factual.
